# SECURITY.md — AI Tuner Workbench

## Ansvarlig fremlæggelse af sikkerhedsproblemer

Vi tager sikkerhed alvorligt. Tak fordi du hjælper med at holde projektet og dets brugere sikre.

---

## Rapportér et sikkerhedsproblem

**Rapportér IKKE sikkerhedssårbarheder som offentlige GitHub Issues.**

Send i stedet en fortrolig rapport til:

- **E-mail:** security@birge.dk *(opdatér med faktisk adresse)*
- **Emne:** `[SECURITY] <kort beskrivelse>`

### Hvad skal rapporten indeholde?

1. Beskrivelse af sårbarheden
2. Trin til at reproducere problemet
3. Potentiel påvirkning (hvilke data eller brugere er i risiko?)
4. Eventuelle forslag til rettelse

---

## Hvad sker der efter din rapport?

| Trin | Tidsramme |
|:-----|:----------|
| Bekræftelse af modtagelse | Inden for 48 timer |
| Indledende vurdering | Inden for 5 hverdage |
| Status-opdatering | Hver 10. dag |
| Offentlig fremlæggelse | Koordineres med dig efter rettelse |

---

## Scope

Disse typer problemer er særligt relevante:

- **Authentication/Authorization bypass**
- **SQL injection / NoSQL injection**
- **Cross-Site Scripting (XSS)**
- **Eksponering af persondata (PII)**
- **Insecure Direct Object References (IDOR)**
- **Server-Side Request Forgery (SSRF)**

---

## Vores forpligtelser

- Vi vil aldrig tage retslige skridt mod sikkerhedsforskere der rapporterer i god tro
- Vi krediterer dig i CHANGELOG.md (med dit samtykke)
- Vi stræber efter at rette kritiske sårbarheder inden for 72 timer
